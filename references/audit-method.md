# 审计方法

先核实 HOME、CODEX_HOME（如存在）、当前目录和可访问路径；命令启动失败时尝试明确 shell、非登录模式和可访问目录，不能假定换机器后路径还有效。

来源分开记录：用户全局指令、当前项目指令、本地技能、系统技能、插件维护技能，以及本会话真正可见的工具。磁盘文件数不是已加载数量，文件修改时间不是调用时间，插件缓存里的多个版本不是同时生效的证明。

脚本只读取显式根目录下的 SKILL.md 和 AGENTS 文件。它跳过记忆、历史会话、备份和目录符号链接；输出包含私人路径，仅作本地分析。需要检查指向其他目录的技能时先确认来源，再显式传入真实路径。

```bash
python3 <技能目录>/scripts/audit.py --root <本地技能目录> --root <全局AGENTS文件>
```

脚本的字符长度、规则片段、同名/同内容与引用检查只是候选线索。阈值可配置，不是官方要求；不计算 tokenizer token。frontmatter 采用保守文本提取，复杂 YAML 要使用可用的正式 YAML 校验器复核。缺失引用可能是模板或解析局限。

逐项判断：
- 触发：具体能力与条件是否在前面？普通请求是否误触发专门流程？
- 入口：当前任务是否被迫读所有分支？哪些领域规则确实需要保留？
- 执行：是否擅自升级依赖、创建多角色、重建已有状态？
- 边界：是否对已授权工作重复询问，或把沉默当批准？
- 完成：是否只交初稿，而用户要求运行、验证、导出或保存？
- 维护：规则归谁维护？改插件缓存是否会被更新覆盖？

对重叠技能比较实际输入、产物、业务状态和调用关系。同名不是重复证据；先收紧入口，避免直接删除。系统和插件代码先形成建议，使用其支持的配置或维护渠道；不要伪造客户端设置。

模型、推理强度、权限、联网及工具开关单独审计。只在实测问题与请求范围支持时调整，不把“更高强度”或“更多工具”当优化默认值。
