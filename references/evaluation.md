# 验证与效果评估

脚本测试：在本技能目录执行 `python3 -m unittest discover -s tests -v`。只使用临时文件，无联网或第三方依赖。

格式验证：若当前客户端提供 skill-creator 验证器，使用它；否则至少检查 name/description、YAML、引用、资源和脚本。启发式 scanner 不替代完整 YAML 验证。

语义检查用具体反例：

| 请求 | 期望行为 |
|---|---|
| 修改一句错别字 | 直接修改，不建立角色和工作流 |
| 分析公开文章 URL | 读取文章，不误启视频生成，不强制启动 CDP |
| 修复功能并运行检查 | 完成实现、相关检查和必要修复 |
| 保存招聘草稿 | 回读保存证据，保持最终提交的授权要求 |
| 导出成片 | 有素材且获授权时继续到实际文件和检查 |
| 整理项目文档 | 处理相关说明，不自动修改记忆 |
| 只读体检配置 | 报告问题，不修改被审计文件 |
| 制作分享包 | 排除私人配置、路径、资料与日志 |

静态场景走查只证明规则之间的逻辑关系。真正效果需新任务对照：固定模型、推理强度、输入、初始状态、工具和验收标准，分别用旧/新配置运行，记录正确性、耗时、不必要询问、返工和保留结果。缺少测量值就留空。

不为比快而取消重要验证，不用修改测试标准取得高分，不把一轮成功当稳定提升。正在运行的会话可能已加载旧规则；用新任务核对实际发现与行为。
